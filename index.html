案例背景

CAT CAFE：貓咖啡廳的會員與點餐管理。

使用者：客人與服務員（店長也是服務員的一種職務）。

要解決的問題：貓咖啡廳的客人除了點飲料和甜點，還會挑選想互動的貓咪，也有人是會員。原本會員資料、來店紀錄與點單都記在紙本，服務員不知道客人來過幾次、誰是常客；店長也無法回答「哪隻貓最受歡迎？」「哪類餐點賺最多？」「每位服務員的業績如何？」，也不知道咖啡和蛋糕還剩多少、要不要補貨。這個資料庫把客人、服務員、貓咪、菜單、來店紀錄、點餐明細與進貨紀錄連在一起，讓服務員能快速查詢客人與消費，也讓店長能用 SQL 做營運分析與庫存管理。庫存量不另外儲存，而是「進貨總數 − 點餐總數」即時算出，避免數字不一致。

資料庫設計

ERD

PK 主鍵；FK 外來鍵；箭頭由外來鍵指向被參照的表。每次來店（visits）可以指定一隻互動的貓，也可以不指定（cat_id 為 NULL）。

自由練習（可新增、修改、刪除資料）

這裡是獨立的練習資料庫，可以執行 SELECT、INSERT、UPDATE、DELETE，不會影響上面題目的預期結果。重新整理或按「重設資料庫」會恢復範例資料。

SQL（可一次執行多句，顯示最後一句的結果）
可以試試看

UPDATE menu_items SET price = 120 WHERE item_id = 2;：把拿鐵改成 120 元。

DELETE FROM customers WHERE customer_id = 6;：刪除沒來過的客人。

DELETE FROM cats WHERE cat_id = 1;：米糕被 visits 參照，會因外來鍵限制而出現錯誤，想想為什麼。
